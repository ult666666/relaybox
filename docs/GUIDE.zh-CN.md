# RelayBox 中文指南

RelayBox 是一个本地 Webhook 收件箱示例，使用 Python 3.11+ 标准库和 SQLite。它展示签名校验、重复投递处理、事务领取、租约令牌、有限重试与死信恢复；不代表生产服务或真实客户使用。

## 快速运行

在项目目录执行：

```bash
python3 -m relaybox --db .local/demo.sqlite3 demo
python3 -m relaybox --db .local/demo.sqlite3 serve --demo-secret
```

访问 `http://127.0.0.1:8787`。演示仅含合成数据，四条记录分别处于排队、租约中、成功、死信状态。`demo` 不覆盖已有数据；再次体验请换一个数据库路径。`--demo-secret` 使用公开的合成演示密钥，不能用于真实数据。

在另一个终端运行 `python3 examples/send_webhook.py`，将同一签名投递发送两次。首次应返回 `202`，第二次返回 `200`。点击页面的 Refresh 查看新记录。

## 状态与恢复

- 相同 ID、相同原始内容摘要：返回已有记录，不新增任务；相同 ID、不同内容：返回 `409`。
- 每次领取都会增加尝试次数，并生成新的租约令牌。租约到期后，旧令牌不能确认或失败提交，即使尚未被其他工作者领取。
- 租约到期前可执行 `renew JOB_ID --token TOKEN --lease-seconds 60`，或调用 `Inbox.renew`。续租只延长到期时间，不减少已有租约、不更换令牌或工作者，也不增加尝试次数。恰好到期时已不能续租；等待 SQLite 写锁后才采样时间。
- 默认最多三次领取。失败后按 2、4 秒等退避，最大 60 秒；最终失败转入死信。过期最终租约在下一次领取时转为死信。
- 手动恢复：`python3 -m relaybox --db .local/demo.sqlite3 replay 3`。仅死信可恢复；恢复重置尝试次数并增加恢复计数。恢复次数由本地操作者控制。
- 控制台只读；工作者通过 CLI 或 Python API 操作，不提供远程工作者接口。

## 有界本地工作者

服务接收合成投递后，在另一个终端执行：

```bash
python3 -m relaybox --db .local/demo.sqlite3 work --receipts .local/receipts --max-jobs 10
```

`work` 最多领取指定次数，找不到已就绪任务就立即停止，不等待未来重试。默认只领取一次；`--max-jobs` 必须是 1–1000 的整数。`--worker` 默认 `local-worker`，`--lease-seconds` 默认 30 秒（范围 0.001–3600）。输出只有 `claimed`、`succeeded`、`failed`、`lost_leases` 计数，不含租约令牌。正常返回退出码 0；处理器失败或丢失租约时为 1；配置错误、手动操作失败或收件箱存储错误为 2。

每个成功处理会写入版本 1 JSON 回执并确认任务。回执只保存投递 ID、原始内容摘要和解析后的合成内容，文件名是投递 ID 与摘要组合的 SHA-256，不使用原始 ID 路径或数据库内任务编号。过期后重新领取时，已有内容逐字节相同的回执直接成功，不重新写入；冲突、损坏或非规范内容明确失败且不覆盖已有文件。通过写完并同步临时文件后原子硬链接发布，最终文件不会只写一半。文件系统必须支持硬链接。

回执目录及父目录必须是受信任的本地目录，不能被其他进程恶意替换。父目录的正常系统别名会规范化；指定回执目录本身和回执文件都不能是符号链接。新目录权限申请为 `0700`，文件为 `0600`，受 umask 和平台规则影响；不改变已有权限。此示例不提供分布式恰好一次或断电持久性保证，强制终止可能遗留临时文件。删除或修改回执会破坏示例的幂等性。

Python 用户可以调用 `relaybox.worker.run_worker(inbox, handler, ...)` 并传入本地幂等函数，或使用 `ReceiptHandler(path)`。处理器正常返回就尝试确认，普通 `Exception` 就记录失败并按原策略重试或进入死信。确认或失败提交时租约已经失效，只增加 `lost_leases`。`KeyboardInterrupt`/`SystemExit` 继续向外抛出，租约留待过期恢复；收件箱存储错误也向外抛出。处理器运行时间不受领取次数上限约束，没有自动续租线程；长任务必须在到期前显式续租或在租约内完成，外部副作用仍需调用方自行保证幂等。

## 解释空闲工作者：只读队列快照

0.4.0 的控制台保留四个持久状态卡片，并增加操作摘要。点击 Refresh，或请求本地 GET `/api/metrics`，可分别查看已就绪/延迟的排队任务、有效租约、已过期且可重领的租约、以及已过期且尝试次数耗尽的租约。`available_at` 恰好等于快照时间时已就绪，`lease_until` 恰好等于快照时间时已过期。过期耗尽的任务仍计入 Leased，直到工作者下一次领取时才转入死信；读取摘要不会领取或更改记录。

最老就绪等待时间按“快照时间减去可领取时间”计算，单位为秒，不代表从接收到现在的年龄或端到端处理耗时。下一次重试/有效租约到期使用浏览器本地时区。没有相应记录时，API 明确返回 null，页面显示说明文字，不会显示零日期或 NaN。摘要包含整个收件箱，最新 100 条列表通过另一个请求获取，可能反映不同提交。页面明确区分两者，并且仅手动刷新。某部分失败时会清空该部分旧值并提示错误，另一部分成功的数据仍可使用；较旧响应不会覆盖较新刷新。

Python 可在现有实例上调用 `inbox.metrics()`。方法仅执行一次聚合 SELECT，并只采样一次时钟；不读取投递标识、摘要、令牌、工作者、错误或内容。返回大小固定，但 SQL 可能扫描全部记录，没有恒定耗时或大规模吞吐量承诺。时钟必须为有限 int/float Unix 秒，范围 0–253402300799（含边界，至 9999 年）；布尔、非有限、负值和越界值抛出 ValidationError。普通 `Inbox(path)` 构造仍会初始化不存在的数据库并设置 WAL，应与只读方法本身区分。`/api/stats` 保持原持久计数格式，`/healthz` 仅表示进程存活。此功能不提供后台监控、自动刷新、处理完成或服务健康保证。

## 一致备份与新路径恢复演练

0.3.0 提供显式本地备份。不能直接复制正在使用 WAL 的数据库主文件，否则可能遗漏已提交任务。选择已存在、可信且私有的本地目录，以及尚不存在的新文件名：

```bash
python3 -m relaybox --db .local/demo.sqlite3 backup .local/snapshot.sqlite3 --timeout 10
python3 -m relaybox verify-backup .local/snapshot.sqlite3
```

在线备份通过只读事务固定已提交快照，再用 SQLite 在线备份 API 复制；包含已提交 WAL 数据，不包含未提交修改。完成后验证结构、完整性和状态计数，转为无需源 WAL/SHM 文件的单个快照，再以独占硬链接发布。已有目标、符号链接、硬链接或遗留的 `-wal`、`-shm`、`-journal` 文件会被拒绝，不覆盖也不删除。JSON 回执只包含规范路径、结构版本、完整性、任务/状态计数、物理 SHA-256 与文件大小；**数据库备份本身仍包含全部内容和私有租约令牌**，必须妥善保护。

切换到恢复路径前，**停止原服务和所有原工作者**，演练期间保持停止。不要预先初始化恢复目标：

```bash
python3 -m relaybox --db .local/recovered.sqlite3 restore .local/snapshot.sqlite3
python3 -m relaybox --db .local/recovered.sqlite3 stats
python3 -m relaybox --db .local/recovered.sqlite3 work --receipts .local/receipts --max-jobs 10
```

处理前将恢复计数与备份回执比较。尝试次数、重试策略、重放次数及所有租约字段逐字段保留。过期租约在下一次领取时处理；未过期租约仍需等待到期。恢复副本是独立收件箱，无法阻止仍在操作原数据库的工作者。快照之后的工作可能再次执行。数据库备份不包含回执目录，必须单独保留/备份原规范回执；崩溃发生在写回执与确认之间时，同样的回执可避免重写，删除或更改回执会破坏此示例幂等性。外部处理器仍需自己的幂等机制，没有跨数据库的恰好一次保证。

只支持操作者拥有的可信 schema-1 文件，不执行迁移、修复、扩展或文件提供的 SQL，也不构成恶意 SQLite 文件沙箱。父目录别名会规范化，指定文件本身不能是符号链接，文件和目录不能被其他进程并发替换。新文件权限申请 `0600`，受 umask 和平台影响；需要原子硬链接，未认证 Windows ACL 或网络文件系统。超时必须为有限的 0.1–60 秒，默认 10 秒；使用共享单调时限检查 SQLite 查询、备份进度和哈希分块。数据库物理大小和页数乘页大小均不得超过 1 GiB。时限不能中断已阻塞的操作系统 I/O；最终目录元数据不做 fsync，强制终止可遗留私有临时文件，没有断电恢复承诺。`verify-backup` 只读验证静止、无旁文件的 DELETE 日志模式快照；活动 WAL 收件箱先执行 `backup`。

安装后运行 `python examples/verify_backup.py`，在源码目录外验证当前安装版的备份 → 验证 → 新路径恢复 → 过期租约领取 → 复用已有回执 → 确认流程。

## 验证与边界

运行 `python3 -m unittest discover -v`。测试包括真实 HTTP 请求、多个 SQLite 连接并发领取、续租与完成竞争、重复投递、旧工作者拒绝、回执重试和 CLI 退出码。安装后用对应环境的 Python 执行 `examples/verify_worker.py`，验证真实安装版 CLI 的签名接收 → 回执处理 → 确认全流程；`examples/verify_install.py` 验证安装版静态资源。

服务仅监听 IPv4 回环地址，采用明文 HTTP、单个 HMAC 密钥。请求上限 64 KiB，每次套接字读取超时 3 秒，同时处理最多 32 个连接。没有对外投递、账户权限、自动清理、自动备份或分布式扩展。任何能访问本地服务的进程都可能读取内容。租约令牌只保护此数据库，不能保证外部操作恰好执行一次。
